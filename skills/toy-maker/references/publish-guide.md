# 官方发布指南与使用协议要点

> 来源（2026-10-29 读取，线上为准）：
> - 发布流程：https://www.bilibili.com/toy/publish/guide
> - 常见问题：https://www.bilibili.com/toy/publish/guide/faq
> - 使用协议：https://www.bilibili.com/toy/publish/agreement （《哔哩哔哩小玩具（bilibili Toy）使用协议》）
>
> 下面是面向开发者的整理，不是协议原文；涉及权利义务的判断请让开发者读原文。

## 一、发布流程（网页端，5 步）

1. **填写页面地址**：系统随机生成，也可自定义；最终地址 `https://www.bilibili.com/toy/<路径>`。发布后不可修改。
2. **上传文件**，三种方式任选：
   - **拖拽 ZIP**：包根目录（或唯一一级子目录）必须有 `index.html`；
   - **拖拽单个 HTML**（`.html` / `.htm`）；
   - **选择文件夹**：平台自动打包成 ZIP。
3. **选择封面**：上传 ZIP 后平台会从包内图片里提取候选，也可单独上传（`.png` / `.jpg` / `.jpeg`）。
4. **填写名称**：HTML 里有 `<title>` 会被自动当作默认名称——所以 `<title>` 要写成你想要的 Toy 名称。
5. **点击发布**：进入审核，通过后自动上线。

推荐的包结构：

```
my-project.zip
├── index.html      (必需，入口)
├── style.css
├── script.js
└── images/
    ├── logo.png    (可作为封面候选)
    └── banner.jpg
```

`scripts/make_release.py` 会把构建产物同时整理成这三种上传形态，外加 CLI 命令和留档文件，见 SKILL.md 第 8 步。

## 二、常见问题（开发相关）

- **白屏**：资源用了绝对路径（`/assets/x.css`）。页面运行在 `/toy/<路径>/` 下，改相对路径或构建工具 `base: "./"`。
- **路由**：推荐 hash 模式（`#/xxx`）；history 模式每个路由都要有真实 HTML，否则刷新 404。页内锚点 `href="#id"` 已支持。
- **审核状态**：审核中 / 审核通过 / 不通过（可看原因修改重提）；系统异常时会一直显示审核中，稍后在「发布记录」查看。
- **更新**：「发布记录」→ 更新按钮，可重新上传文件、换封面、改名称；更新同样要审核。
- **框架项目**：只传构建产物（`dist`），先 `npm run build`。
- **大小**：ZIP 不能超过账号生效的包体上限，以发布页「包体大小」显示为准（普通账号默认 50MB，可申请更大）。入口 `index.html` 解压后 ≤1MB。
- **文件白名单**（只有这些后缀会被发布，其余自动过滤）：
  - 网页与脚本：`.html .htm .css .js .json .wasm`
  - 数据：`.data .md .csv .tsv`
  - 图片：`.png .jpg .jpeg .gif .svg .webp .ico`
  - 字体：`.woff2 .woff .ttf .eot`
  - 音频：`.mp3 .wav .ogg .m4a`
  - 视频：`.mp4 .webm`
  - 引擎资源：`.atlas .ani .part .nani .unityweb`
  - 不在列表里的常见坑：3D 模型 `.glb/.gltf/.bin`、`.txt`、`.xml`、`.fnt`、`.ktx2`、Cocos 的 `.cconb` 等——换成白名单格式（例如模型数据改存 `.data`/`.json` 后在代码里按二进制读取、文本改 `.json`/`.md`），或询问平台。

## 三、使用协议：开发时会踩到的条款

**内容与功能（除哔哩哔哩书面同意外）**
- 2.5 不得嵌入或调用：广告代码、**统计代码**、支付/充值/打赏组件、抽奖/返利/导购组件、**第三方 SDK**、第三方登录、用户数据收集组件。
- 2.6 不得嵌入指向非平台方拥有或控制的第三方链接。
- 2.7 不得通过远程脚本、iframe、跳转、外链资源、动态加载、热更新等方式**规避审核或实质变更已审核内容**——依赖库打包进项目，不要运行时从外部拉代码；功能变更走「更新」重新审核。
- 3.5(3) 未经许可不得使用「哔哩哔哩」「bilibili」「22娘」「33娘」「小电视」等平台商业标识及其变体——**Toy 名称、封面、图标里别带这些字样**。
- 3.5(4) 不得表达或暗示与哔哩哔哩存在合作/认可关系。
- 三.1(4)(5) 与平台本身功能相同、或界面风格让用户以为来自平台官方的项目，平台可以终止服务。

**数据（第四条）**
- 收集任何用户数据都要事先取得明确同意，只收集运行必需的数据，并告知目的、范围、用途。
- 不得收集账号密码、关注列表/关系链、银行账号等敏感信息。

**用户产生的内容**
- 3.2 用户通过你的项目产生的内容由你负责；出现违规内容要及时删除或采取措施——这也是 UGC 要非常谨慎的原因。

**留档（2.8）**
- 平台不承诺永久存储、备份、恢复或版本回溯——**开发者自行保存项目文件、源文件和备份**。`make_release.py` 生成的留档目录就是为此准备的。

**知识产权与运营（第五条）**
- 项目知识产权归开发者或原始权利人；开发者要确保素材、代码、字体、音乐、模型、开源组件等都有合法权利或授权。
- 发布即授予平台服务期内非排他、免费的全球许可，用于展示、分发、缓存等；平台还可以在站外宣传推广项目、使用其名称和素材。
- ⚠️ 协议写明**服务期内平台拥有该项目的独家运营权**，未经书面同意不得自行或授权第三方在其他渠道运营该项目。这与 FAQ「Toy 不要求独家」的说法不一致——开发者如果打算在其他平台同时发布同一个项目，提醒其以协议原文为准、必要时先向平台确认，不要替开发者下结论。

**平台权利**
- 平台可随时审核、删除或屏蔽项目，可能要求修改/更新/参与运营活动；违规可警告、删除、限制或终止服务。
- 违规项目即使修改后仍可能被删除，可作为新项目重新上传。
