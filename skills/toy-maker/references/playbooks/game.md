# 游戏类 Toy 手册（休闲 / 动作 / 养成 / 模拟经营 / 解谜）

分类：`GAME`。最挤（约 1960 个），也是本周必玩入选最多的类型。**选了「游戏」分类，未成年人无法游玩**——
如果是全年龄的轻玩具，考虑「互动玩法」。

## 成功结构
1. **零门槛开局**：点击任意位置开始；第一局 10 秒内出现第一个「爽点」（得分、暴击、怪叫、升级）。
2. **单局短、可重开**：手机竖屏 1–3 分钟一局；横屏动作游戏要接容器能力（见 recipes.md §10）。
3. **熟梗 × 新玩法**：B站熟悉的角色/梗/游戏 IP 降低理解成本，玩法给出新鲜感（版权先过一遍）。
4. **一个清晰的长期目标**：排行榜名次、收集图鉴、解锁皮肤/角色、养成数值。
5. **结算页**：分数 + 名次 + 「再来一局」+ 分享卡/截图点。

## 增长与留存
- 官方数据：经典小游戏 × 排行榜复玩率 32%，「能刷分、能比排名」是复访动机——排行榜别省。
- 头部标配：云存档 + 排行榜 + 「关注/三连解锁额外奖励」。
- 养成类收藏率极高（每千次 ~26）——提醒玩家「收藏 Toy 方便回来」。
- 持续更新：新角色、新关卡、节日活动；里程碑纪念（游玩破 N 万送皮肤）。
- 视频联动：首发一条横屏实况 + 多条竖屏高光；在 Toy 内放「去看攻略视频」用 `navigate({type:'video'})`。
- 系列化：同一个模板换题材出续作，用合集 Toy 串起来。

## 推荐 SDK
`setCloudStorage/getCloudStorage`、`submitScore/getRankList/getMyRank`（5 个榜位可做总分/通关时间/收集数）、
`getAuthorRelation` + `getVideoUserActions`（额外奖励）、`setContainerMode/onContainerChange`（横屏）、`getUserProfile`。

## 坑
- 关注/三连只能解锁额外内容，主线必须免交互可玩；复活/强化处引导关注，别放在上传成绩前强制。
- 排行榜前端提交可被刷，比赛性质强的要后端验签；被刷就在管理端拉黑。
- Unity 关压缩、别带 mp4；入口 index.html ≤1MB；WebGPU 要 WebGL 兜底。
- 频率限制：结算时提交一次分数、关键节点存档。
