## 1. 包与构建

- 上传形态：`.zip` / `.html` / `.htm` / 文件夹。zip **根目录**（或唯一一级子目录）要有 `index.html`。
- **入口 index.html 解压后 ≤ 1MB**（硬上限，create/update/preview 均拦，报 `307000`）。大脚本、样式、内嵌图片、内联 JSON 都拆成独立文件。单文件打包器（TurboWarp 选 Plain HTML、vite-plugin-singlefile 等）产出的入口基本都会超；TurboWarp 改选 Zip 导出。
- 其他 HTML 没有硬上限，但 ≥12MB 时每次访问都慢（文档不能被缓存）。
- 整包上限 50MB，更大需在「创作者设置」申请。
- 只有白名单后缀会被发布，可执行文件、后端脚本被过滤。Cocos 的 `.cconb.bin` 等编译文件会被过滤——用前确认。
- 资源相对路径；页面跑在 `/toy/<slug>/` 下，`/assets/x.js` 会解析到站点根导致白屏。JS 里也别 `location.href = '/xxx'`。
- 路由：hash 模式最稳；history 模式每条路由都要有真实 HTML。页内锚点 `href="#id"` 已支持。
- 产物文件名带 contenthash、第三方依赖拆 vendor chunk，平台能跨版本复用未变的资源，更新后玩家少下载。`public/` 下的文件不带 hash，大资源尽量走构建管线。
- 只传构建产物，别带 `src/`、`node_modules`、`.git`、`__MACOSX`、`.DS_Store`、`toy.yaml`。

## 2. 运行环境与兼容

- 运行方式：`www.bilibili.com/toy/<slug>/` 是平台外壳（带点赞/评论/收藏侧栏和 `toy-host.js`），作品本体在一个沙箱 iframe 里，域名是 `www.bilibilitoy.com/toy/<slug>/<id>-v<版本>/`。sandbox 允许 scripts、forms、popups、same-origin、downloads、pointer-lock 和「用户手势触发的顶层跳转」——所以 `localStorage` 按 bilibilitoy.com 域隔离，下载要用户点击触发，自动跳转顶层会被拦（用 `toy.navigate`）。
- 主场是 B站 App 内 WebView；电脑浏览器也能玩并支持点赞、评论、关注 UP；鸿蒙版能进但无点赞评论；国际版功能较少。
- 技术选型：Three.js、Unity、Canvas 2D 等可用；Godot 3.x 尚可、4.x 需全量下载且兼容性一般，更适合单机。
- WebGPU 取决于 App WebView 和系统/GPU/驱动，必须用 WebGL/WebGL2 兜底并真机测。
- **Unity 黑屏**：多半是构建开了压缩，或包里有 .mp4。关压缩、去掉视频或改 CDN 加载。
- 外部资源 FAQ 说暂未禁止，但《使用协议》2.5/2.7 不允许未经同意接入第三方 SDK、用远程脚本/动态加载规避审核——**代码和依赖一律打包进项目**，外链只用于大体积静态素材（并预期权限会收敛）。**不能用 iframe 嵌外部网页**；播放 B站视频用 player.bilibili.com 的播放器 iframe。
- 横竖屏/沉浸：SDK 容器能力需 App 9.9.0+；旧版本做旋转自适应。沉浸模式下评论栏隐藏、顶部有胶囊，交互元素避开安全区。
- 全屏横屏后画面变小：在 `onContainerChange` 里处理 viewport 变化并调用引擎的缩放刷新（Phaser `game.scale.refresh()`），加延时重试兜底。
- 多机型按键适配：允许玩家自己调按键位置。
- 「添加到桌面」已支持，但要识别环境（不同端能力不同；iOS 默认浏览器非 Safari 时可能打不开）。
- 本地存储易丢（清缓存、系统清理），重要数据用云存档。云存档多端同步前提是测试时已授权登录。
- 陀螺仪等传感器、用户位置、超广角摄像头：暂不支持。
- 只有图片能保存到本地，Toy 内不能生成并下载视频。
- 没有独立测试环境：用「链接访问 / 密码访问」发布 + 小号测；或两个 Toy 区分测试版与正式版。平台计划推出「调试版本」（免审、仅作者可见）。
- 预览与正式环境可能有细微差异，「预览正常发布后打不开」带复现信息找官方。
- URL 打不开：检查是否完整，分享时带上 `index.html`；或 slug 与历史条目重复——换 slug 重新发布。

## 3. 数据、存档、排行榜

- 云存储：按「登录用户 + Toy」隔离，单 Toy 最多 128 个 key，value ≤1024 字节字符串，`__` 开头的 key 是保留的。
- 共享存档：同一玩家在多个 Toy（含被授权的合作作者的 Toy）间共享一份数据；在创作中心「共享存档」创建拿到 `st_xxx` 标识，或用 CLI `toy shared-storage` 管理。**不是跨玩家共享**，跨用户 KV 暂不支持（创意工坊、玩家间互读存档都做不了）。
- 多 Toy 串联关卡：Toy 间用 `toy.navigate({ type: 'toy', ... })` 跳转 + 共享存档延续进度。
- 排行榜：5 个榜位（board 1–5），周期 all/month/week/day；分数为整数，范围 -16777216 ~ 16777215（Float32 精确整数区间）。只保留历史最高分，同分先到先得。需要存「数字以外」的数据就用多个榜位分别存再合并展示；需要更大数值就在本地做偏移/缩放后再上传（榜单 SDK 不负责展示格式）。
- 移除榜单中的某个用户会同时清掉他在所有榜位的记录。
- 反作弊：可在管理端拉黑刷分账号；纯前端上报无法根治，核心思路是「每局结果后端运算/验签」。关注、充电查询都是前端校验，可被破解——只适合做附加玩法或精神奖励。
- 频率限制：云存储、共享存档、排行榜、输入检测按 Toy 共享额度，超限 `307044`。官方 FAQ 曾提到量级，但 SDK 文档明确阈值不公开且可调——不要写死数字。大批新用户涌入时最容易触发：本地缓存 + 关键节点保存 + 加载中状态 + 指数退避。
- 联机：需自建后端（并用云存档减轻服务器压力）。自建后端/调用自有 API 要先开通权限。
- 保护核心逻辑：纯前端易被还原，核心逻辑放自建后端，配合鉴权与 SDK。

## 4. 合规红线（重要）

最终以《Toy用户协议》为准。下面是 FAQ 明确列出的禁止项和灰区处理：

**明确禁止**
- 放置广告；接广告联盟 SDK。
- 跳转站外链接；出现第三方平台登录/跳转（QQ、TapTap 等）。Toy 默认就是 B站账号登录。
- 爱发电、微信/支付宝收款码等第三方收款方式（违规会被限流或下线）。想引导充电，就引导到作者的 B站个人主页。
- 侵犯版权（素材、BGM、音效、商标）。
- 让用户自建昵称/头像——只能用 SDK 返回的、或系统随机生成、或提供预置候选让用户选。
- 以锁死基础功能为条件提供附加体验；必须有至少一份**免交互可见**的内容。
- 常驻式引导干扰体验。
- 未经授权的 UGC 能力：自由输入后公开展示、上传文字/图片/拍照、聊天室、画板等。用 iframe 实现聊天室同样不行。

**灰区与做法**
- 必须有输入框：接入内容安全审核（SDK `checkInputSafety`，`unavailable` 不能放行），且不允许用户上传底图；最终以平台审核结论为准。
- 含自由绘制的 Toy：发布时必须开启访问者水印（CLI `--watermark`）。
- 强制关注：不推荐放在主线（比如上传成绩必须关注）；放在复活、强化、获取新武器等环节。
- 模拟真实机构/App 界面（如模拟银行）：显著位置标「这并非真实 xx 界面」。
- 跟热点：可以，注意措辞，不涉黄涉政，不违反社区公约。
- 名称、封面、标题、图标：不涉政、不涉黄、不侵权、不用他人商标。
- 站内跳转：跳自己的 B站主页可以；`wiki.biligame.com` 等可蓝链的站内域名不算站外；尺度与个人主页、视频简介一致。
- b23 短链：不建议，约一年后失效导致打不开。
- 问卷：可以，需自建后端，不得收集个人敏感信息。
- 赞助名单：可以展示，合规要求同视频里感谢充电粉丝。
- `toyOpenId`：只用于当前 Toy 内关联用户，不写埋点、不进公开日志；SDK 不提供 UID/MID。

被下架或审核不通过：先自查自由输入、外链、不合规资源；再看内测群公告里的审核咨询入口。

## 5. 发布、审核、可见性

- 权限：需先申请 Toy 权限（每周二、四集中处理）；PC 创作中心侧边栏有 Toy 入口。无需先提交创意。
- 审核通常 10 分钟内；卡审可联系工作人员。多次修改攒一起更新，减少审核次数。
- 新建 Toy 的封面与图标也要审核，审核中可能不显示。
- 可见性三档可互转：
  - 所有人可见：自动发一条公开动态，可被搜索、推荐、分享，进 Toy 广场。
  - 链接访问：只有拿到链接的人能访问，关联动态不出现在首页/搜索等。适合测试。
  - 密码访问：系统生成密码，动态隐藏封面和完整标题。
  - 从链接/密码转公开，关联动态随之公开；反向则隐藏。
- slug 可自定义（字母数字下划线连字符，≤64 字节），**发布后不可改**。
- 分类 Tag、作品图标可自定义；系统自动分类可能有偏差，自己改。选「游戏」→ 未成年人无法游玩（未成年开发者测试时先别选）。
- 「参与活动」：发布时圈选活动 code（CLI `--activity`），Toy 需符合活动要求。
- 一个账号可发布多个 Toy，没有数量限制；可无限次更新。
- 用 Safari 在网页端上传发布会异常，用 Chrome（或直接用 CLI）。

## 6. 视频联动与增长

- 绑定视频：只能绑本人发布的视频；一个 Toy 可绑多个视频，一个视频只能绑一个 Toy。绑定后 Toy 出现在视频下方入口——**这是拿视频流量的前提**，同时在简介/评论区挂链接。
- 投放组合：一条横屏 + 多条竖屏爽点切片 + 图文。部分 Toy 竖屏短视频带来的流量占比可达 37%–50%。
- 联合投稿官方账号：UP 主权益等级 ≥4 且粉丝 ≥1000；稿件 1 万+ 播放后评估；投稿带 tag `bilibilitoy` 和话题「哔哩哔哩Toy创意挑战」。
- 推流：按官方申请表填（带指定 tag 和话题），一般 24 小时内反馈，通过后私信通知「已推」；封面点击率越高推流越久，首日数据影响大。
- 分享战绩：可把 Toy 入口以二维码放进分享图（`toy.getQrCode`）。
- 新作曝光：蹭热门标签、持续维护、常发视频、拉玩家群；参考官方《Toy运营白皮书》。
- 玩家找回玩过的 Toy 路径少：动态置顶、提醒粉丝收藏。

## 7. 数据统计与推荐位

- 浏览量只统计**B站 App 内有登录态**的访问。
- 数据在 Toy 详情页顶部、发布平台数据看板（含次日留存率），或 CLI `toy stats`。
- 浏览量 >500 收录进「哔哩哔哩玩具铺」，每周一更新。
- Toy 广场：只收录「所有人可见」的 Toy，无体验量门槛；「本周必玩」每周一晚更新，运营按当周体验量、互动、质量从「娱乐」「工具」两条赛道精选 6–10 个（工具赛道相对不拥挤）。
- 「今日推荐」系统按游玩量自动产生，非人工。
- PC 上可在 Toy 广场「我创作的」看全站 PV 排名。
- 访问量异常：平台会修正异常数据；关键数值可做服务端校验防刷。

## 8. 商业化边界

- Toy 本身无直接收益，价值在于给关联视频带流量；已知变现案例多为「商单 + 视频」。
- 不支持支付、广告联盟。可用 `getAuthorRelation().isCharging` 判断包月充电做定制体验（前端校验可被破解，只做附加/精神奖励）。「充电畅玩」可基于充电检测 + 自建 Toy 索引。
- FAQ 说「不要求独家」，但《使用协议》第五条写明服务期内平台拥有项目的独家运营权——两者冲突时以协议原文为准，打算多平台发布先问平台（见 publish-guide.md）。Toy 源码可作为资产在 B站小店售卖；Toy 内接小店带货暂未开放。

## 9. 支持渠道

- Toy 开发者小站发帖（帖子也要审核，引导站外注册类内容会被拒）。
- FAQ 评论区留言。
- 审核问题看内测群公告里的审核咨询入口。
- 官方建议「配合 Agent 使用」：把开发文档和 SDK 文档喂给 AI 编程助手——也就是本 skill 的用途。
